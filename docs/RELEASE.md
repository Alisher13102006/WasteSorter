# Выпуск приложения

## Версионирование (задание 2)
SemVer `MAJOR.MINOR.PATCH`, задаётся в `app/build.gradle.kts` (`versionMajor/Minor/Patch`).

| Часть | Когда повышать | Пример |
|-------|----------------|--------|
| MAJOR | несовместимые изменения: удаление функции, миграция данных без возврата, повышение minSdk | 1.x -> 2.0.0 |
| MINOR | новая функция, старое поведение сохраняется | 1.0.0 -> 1.1.0 |
| PATCH | только исправления, hotfix | 1.2.0 -> 1.2.1 |

`versionCode = MAJOR*10000 + MINOR*100 + PATCH` (1.2.1 -> 10201). Он только растёт: магазин не примет
сборку с тем же или меньшим versionCode. Каждой версии соответствует git-тег `vX.Y.Z`; CD проверяет,
что тег совпадает с версией в Gradle.

## Варианты сборки (задание 3)
| Вариант | applicationId | API | Иконка | Подпись |
|---------|---------------|-----|--------|---------|
| debug | `kz.wastesorter.app.debug` | dev.api.wastesorter.kz | оранжевая, «Сортировка (Debug)» | debug-ключ |
| staging | `kz.wastesorter.app.staging` | staging.api.wastesorter.kz | синяя, «Сортировка (Staging)» | debug-ключ, R8 включён |
| release | `kz.wastesorter.app` | api.wastesorter.kz | зелёная | upload-ключ |

Все три ставятся на одно устройство одновременно. Код при этом остаётся в пакете `com.example.wastesorter` (namespace):
namespace и applicationId независимы, поэтому ID в магазине поменяли без переноса исходников. Секреты: `API_KEY` и `RELEASE_*` берутся из переменных
окружения (CI), затем `local.properties`, затем `keystore.properties`. Шаблон — `keystore.properties.example`.

## Оптимизация R8 (задание 4)
```
./gradlew assembleRelease -Pr8=false   # без оптимизации
./gradlew assembleRelease              # R8 + shrinkResources
```
| Сборка | Размер APK |
|--------|-----------|
| release без R8 | 32,0 МБ |
| release с R8 и сжатием ресурсов | 23,3 МБ (−27 %) |
| AAB (release) | 13,6 МБ |

Большую часть APK занимают не код, а нативная библиотека TensorFlow Lite (~6–7 МБ на каждую
архитектуру процессора: arm64-v8a, armeabi-v7a, x86, x86_64) и модель `waste_model.tflite` (2,4 МБ).
R8 сжимает только код и ресурсы. Поэтому AAB выгоднее: Google Play отдаёт устройству split-APK
только с его архитектурой, и пользователь скачивает примерно 9–10 МБ.
Классы `org.tensorflow.lite.**` R8 не переименовывает: их вызывает нативный код через JNI (`rules.keep`).
Проверено: release-сборка с R8 распознаёт пластиковую бутылку (72 %).

`mapping.txt`: `app/build/outputs/mapping/release/mapping.txt`. Сохраняется для каждой версии
(артефакт CI + вложение GitHub Release + автозагрузка в Play/Crashlytics). Без него стектрейс из релиза не прочитать: например, `WasteClassifier` в release превращается в `tn1`.

## Подпись (задание 5)
- Upload key: `~/.android-keys/wastesorter-upload.jks`, RSA 4096, alias `upload`, срок 10000 дней.
  Им подписывается то, что загружается в Play Console.
- **App signing key** хранит Google (Play App Signing). Им Play переподписывает APK, которые получают пользователи.
- Потерян upload key: приложение живо, владелец аккаунта запрашивает сброс upload-ключа в Play Console (~2 дня).
- Потерян ключ подписи без Play App Signing (RuStore, GitHub, прямая установка): обновить приложение
  невозможно. Нужен новый applicationId, а пользователи должны удалить старую версию.
- Хранение: файл вне репозитория (права 600), пароли в менеджере паролей, копия на зашифрованном
  офлайн-носителе. В CI — base64 в Secret `RELEASE_KEYSTORE_BASE64`.

## Форматы и установка (задание 6)
| | AAB | APK |
|-|-----|-----|
| Для чего | Google Play (обязателен с 2021) | RuStore, GitHub Releases, прямая установка |
| Установить напрямую | нельзя | можно |
| Размер на устройстве | Play собирает split-APK под устройство | один файл под все устройства |
| Подпись у пользователя | ключ Google (app signing) | ваш ключ |

```
./gradlew bundleRelease     # app/build/outputs/bundle/release/app-release.aab
./gradlew assembleRelease   # app/build/outputs/apk/release/app-release.apk
adb install -r app/build/outputs/apk/release/app-release.apk
```
Проверить AAB локально: `bundletool build-apks --bundle=app-release.aab --output=app.apks --connected-device`
и `bundletool install-apks --apks=app.apks`.

**Установка APK на телефон:**
1. Скачать `app-release.apk` со страницы GitHub Releases.
2. Открыть файл. Android спросит разрешение: «Настройки → Приложения → Специальный доступ →
   Установка неизвестных приложений → [браузер или Файлы] → Разрешить».
3. Нажать «Установить». Play Защита может показать предупреждение: «Подробнее → Всё равно установить».
4. После установки разрешение для браузера лучше снова выключить.

## Публикация (задание 7)
Канал: Google Play, внутреннее тестирование (или GitHub Releases: тег `v*` сам создаёт релиз с APK).
1. Play Console → Создать приложение → `kz.wastesorter.app`, бесплатное.
2. Тестирование → Внутреннее тестирование → Создать выпуск → загрузить `app-release.aab`.
3. Ввести «Что нового» (`fastlane/metadata/android/whatsnew`), сохранить, «Проверить выпуск», «Начать развёртывание».
4. Добавить тестировщиков (список email) и отправить им ссылку для участия.

Карточка магазина (задание 8): `fastlane/metadata/android/<язык>/`: название, краткое и полное описание,
`images/icon.png` 512×512, `images/featureGraphic.png` 1024×500, 4 скриншота в `phoneScreenshots/`.
Категория: «Образование» (или «Инструменты»). Возрастной рейтинг (анкета IARC): нет насилия, покупок,
общения и геолокации → 3+ / PEGI 3 / «Для всех». Политика конфиденциальности: `PRIVACY_POLICY.md`
(публикуется через GitHub Pages). Data Safety: `docs/DATA_SAFETY.md`.

## Поэтапный выпуск (задание 12)
| Способ | Как | Плюсы | Минусы |
|--------|-----|-------|--------|
| Закрытое / внутреннее тестирование | только список тестировщиков | без риска для пользователей | мало устройств, нет реальной нагрузки |
| Staged rollout | 1 % → 10 % → 50 % → 100 % production | баг виден на малой доле, раздачу можно остановить | медленнее, у пользователей разные версии |
| Полный выпуск | сразу 100 % | быстро | баг сразу у всех, откатить нельзя |

План: internal (1 день) → production 1 % (24 ч) → 10 % (48 ч) → 50 % (48 ч) → 100 %.
Доля задаётся в `release.yml` (`userFraction`) или в Play Console («Управление выпуском»).

**Раздача останавливается** («Остановить развёртывание»), если по сравнению с прошлой версией:
- crash-free users < 99,5 % или крэши выросли больше чем в 2 раза;
- ANR rate > 0,47 % (порог плохого поведения Android Vitals) или холодный старт вырос на 20 %+;
- средний рейтинг новой версии < 4,0 или за сутки пришло 3+ отзыва «не работает»;
- в Crashlytics появилась новая fatal-ошибка, которая затрагивает 0,5 %+ сессий.

## Hotfix и «откат» (задание 14)
Магазины не умеют откатывать версию у пользователя: установленная сборка остаётся, а версия с меньшим
versionCode не установится поверх (это защита от downgrade-атак). Остановка rollout только перестаёт
раздавать новую версию тем, кто её ещё не получил. Поэтому «откат» = новая сборка с бо́льшим versionCode.

Заменители отката:
- **feature flags / Remote Config**: проблемную функцию выключают сразу, без релиза (`FeatureFlags`);
- **принудительное обновление**: `min_supported_version` в Remote Config + Play In-App Updates IMMEDIATE (`UpdateChecker`);
- **hotfix**: ветка от тега, исправление, PATCH+1, ускоренный выпуск.

Хронология учебного инцидента 1.2.0 (`git log --oneline v1.1.0..v1.2.1`):
| Время | Событие |
|-------|---------|
| T+0 | 1.2.0 (10200) выпущен на 10 %: «Эко-статистика» (сколько предметов какого вида отсортировано) |
| T+15 мин | Crashlytics: новая fatal-ошибка `ArithmeticException: divide by zero` в `EcoStats.percent` при запуске; crash-free users 100 % → 61 % |
| T+20 мин | Rollout 1.2.0 остановлен; флаг `eco_stats_enabled=false` в Remote Config: карточка не рисуется, крэш прекратился |
| T+1 ч 30 мин | 1.2.1 (10201) с исправлением прошёл CI, загружен в internal, затем production 10 % |
| T+2 ч | `min_supported_version = 10201`: пользователи 1.2.0 получают принудительное обновление |

Время восстановления (MTTR): ~20 мин до нейтрализации флагом, ~2 ч до исправленной версии.
