# Политика поддержки (задание 15, часть Б)

## Минимальная версия ОС
- Сейчас `minSdk = 24` (Android 7.0), это примерно 98 % активных устройств.
- Повышать minSdk можно не чаще раза в год, когда доля версий ниже нового minSdk меньше 3 %
  (Android Studio → Distribution) или когда этого требует ключевая библиотека.
- Повышение minSdk = MINOR-версия. Пользователи старой ОС остаются на последней совместимой
  версии: Play сам перестаёт предлагать им обновления. За 1 релиз до этого — объявление в «Что нового».

## targetSdk и зависимости
- Google Play требует targetSdk не старше года от последней версии Android. Новые приложения и
  обновления — до 31 августа каждого года. План: поднимать targetSdk в мае–июне, после бета-версии Android.
- Зависимости: ежемесячно Dependabot/`./gradlew dependencyUpdates`, ежеквартально мажорные (AGP, Kotlin,
  Compose BOM, Firebase BOM). Обновления безопасности — сразу (P0).

## Жизненный цикл версий

| Статус | Что значит |
|--------|-----------|
| Current | последняя MINOR, получает новые функции и исправления |
| LTS | предыдущая MINOR, 6 месяцев получает только исправления критических ошибок и уязвимостей |
| EOL | не поддерживается; через `min_supported_version` в Remote Config включается принудительное обновление |

Пример: 1.2.x — Current, 1.1.x — LTS до 05.2027, 1.0.x — EOL.

## Резервные копии

| Что | Где | Как часто |
|-----|-----|-----------|
| Upload keystore + keystore.properties | менеджер паролей + зашифрованная флешка (2 копии в разных местах) | при создании, проверка раз в квартал |
| Репозиторий | GitHub + зеркало (GitLab / локальный `git clone --mirror`) | при каждом push / раз в неделю |
| mapping.txt каждой версии | GitHub Releases + Crashlytics | при каждом релизе |
| Секреты CI, google-services.json | менеджер паролей | при изменении |

## Инциденты и уязвимости
1. **Обнаружение:** оповещение Crashlytics или Vitals, отзыв, issue, письмо из `SECURITY.md`.
2. **Оценка (≤ 30 мин):** приоритет P0–P3, сколько пользователей затронуто, в какой версии.
3. **Сдерживание:** остановить rollout, выключить функцию флагом, при уязвимости — отозвать ключи API.
4. **Исправление:** ветка `hotfix/x.y.z` от тега, тест, PATCH+1, выпуск через internal → production 10 % → 100 %.
5. **Коммуникация:** ответы на отзывы, «Что нового», при утечке данных — уведомление пользователей и магазина.
6. **Разбор (≤ 3 дня):** причина, MTTR, тест-регрессия, пункт в чек-листе релиза.
